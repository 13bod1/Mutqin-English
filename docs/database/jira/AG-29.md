## Epic Scope & Architectural Invariants
- Encompasses the foundational relational database layer for the Mr. Adel Mostafa EdTech platform.
- Canonical PostgreSQL 16 schema comprises 20 base tables, 1 analytical view (`v_student_leaderboard_tiers`), and 8 domain ENUMs.
- Packaged SQLite development database comprises 21 base tables (extra `password_reset_otps`) and same view.
- Forensic audit trail in `admin_audit_logs` enforces WORM (Write Once Read Many) immutability via trigger-based DELETE and UPDATE blocks (`fn_prevent_audit_log_modification()`, OWASP A09).
- Hard deletion of administrators is vetoed by the WORM trigger on `admin_audit_logs`, protecting forensic integrity. Forensic policy is preserved without weakening.

## Documented Disclosures & Invariant Policies
1. **Schema Parity & Legacy Table Deviation:** Canonical PostgreSQL 16 contains 20 base tables + 1 view; SQLite contains 21 base tables + 1 view. The extra `password_reset_otps` table in SQLite is a backward compatibility deviation observed from 5 immutable tests in external `test_security_and_hardening.py` (AST-verified: `test_sec_16_otp_expiry_enforcement`, `test_sec_17_otp_single_use_replay_prevention`, `test_sec_18_otp_brute_force_max_attempts_blocked`, `test_sec_19_otp_phone_sanitization`, `test_sec_27_otp_rate_limiting_and_chronological_ttl_invariant`); this is an observed legacy fixture dependency, not proof of an intentional business decision, and no full parity is claimed.
2. **Password Validation Boundary:** Data layer password check is a string length check (`len >= 20`). Cryptographic hash validation (Argon2id/bcrypt) is an application and crypto tier boundary responsibility, not an automatic standalone database flaw.
3. **PostgreSQL 16 Status (Blocker Resolved):** Prior host blocker is RESOLVED via standalone portable PostgreSQL 16.6 verification (14/14 automated SQL probes passed on port 5433). Docker daemon, production deployment, and 105 tests on PG remain unverified.
4. **Separate Verification Accounting:** In-memory SQLite (105 tests passed) and PostgreSQL 16.6 (14 probes passed) are distinct verification baselines and must not be merged into an unqualified total. See [evidence/pg-runtime-summary.md](./evidence/pg-runtime-summary.md).
5. **Future CASCADE -> RESTRICT Proposal:** The architectural proposal to migrate foreign keys from CASCADE to RESTRICT is NOT implemented in current DDL; existing condition is documented factually.
